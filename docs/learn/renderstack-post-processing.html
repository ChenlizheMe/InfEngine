RenderStack and reusable post-processing

Let the pipeline own frame structure, let Effect assets own reusable settings, and let the scene bind them through stable mount points.

In this chapterMental modelEffect assetsCustom pipelineCustom effectPractical rules

Three responsibilities

  • RenderPipeline defines shadows, geometry routes, sky, EffectStages, and screen UI.
  • RenderStack is the scene component that selects a pipeline and mounts ordered effects.
  • RenderEffect is a reusable, material-like asset containing one effect type and its live parameters.

Create one GameObject with a RenderStack, choose a pipeline, then add .effect or .effectgroup assets to its stages. Each stage is an ordered list: reordering slots changes execution order, and disabling a slot keeps the reference without running it.

An EffectStage is a mount point.

Parameter edits advance the live effect revision. They do not rebuild the graph unless a registered parameter changes topology.

Reusable Effect assets

A .effect document uses a stable feature ID and JSON parameters.

{
  "$schema": "infernux.render_effect",
  "dependencies": [],
  "feature_type": "infernux.post.bloom",
  "parameters": {
    "intensity": 0.8,
    "max_iterations": 5,
    "scatter": 0.7,
    "threshold": 1.0,
    "tint": [1.0, 1.0, 1.0, 1.0]
  }
}

Editing the asset Inspector or its inline RenderStack slot changes the same shared live asset. An .effectgroup stores an ordered chain whose entries reference assets by GUID and a readable, recoverable path_hint.

{
  "$schema": "infernux.render_effect_group",
  "entries": [
    {
      "entry_id": "bloom",
      "asset": {
        "guid": "",
        "path_hint": "Assets/Rendering/Bloom.effect"
      },
      "enabled": true,
      "overrides": {}
    }
  ]
}

Runtime parameter changes

from Infernux.renderstack import RenderStack

stack = RenderStack.instance()
if stack is not None:
    bloom = stack.get_effect("final", 0)
    if bloom is not None:
        bloom.set_float("intensity", 1.2)
        current = bloom.get_float("intensity")

Typed accessors cover float, int, bool, vector2, vector3, vector4, and color, with set_param() and get_param() for generic values. Loaded assets are shared; clone one for isolated runtime-only state.

Write a custom pipeline

Python is the public entry point. New pipelines override define(); the declarative compiler validates queue ownership and effect scope before allocating RenderGraph resources.

from Infernux.renderstack import Path, Queue, RenderPipeline


class MixedPipeline(RenderPipeline):
    name = "Mixed Pipeline"

    def define(self, pipeline):
        pipeline.frame(hdr=True, msaa=4)
        pipeline.shadows(resolution=4096)
        pipeline.lighting(clustered=True)

        with pipeline.opaque() as opaque:
            with opaque.layer("Stylized Objects") as layer:
                # Forward only for materials in Queue 1-100.
                layer.forward(Queue(1, 100)).effects("low_queue")

                # Prefer Deferred for 101-200, with a Forward+ fallback.
                layer.deferred(
                    Queue(101, 200),
                    fallback=Path.FORWARD_PLUS,
                ).effects("middle_queue")

                # Process both route results together.
                layer.effects("stylized_combined")

            opaque.otherwise().forward_plus()
            opaque.effects("opaque_only")

        pipeline.effects("after_opaque")
        pipeline.sky()
        pipeline.effects("after_sky")

        with pipeline.transparent() as transparent:
            transparent.otherwise().forward_plus()
            transparent.effects("transparent_only")

        pipeline.effects("final")
        pipeline.screen_ui()

Queue intervals are inclusive. Opaque conventionally uses 0-2500, transparent uses 2501-5000, and the supported range is 0-9999. In one domain, a queue may be claimed by only one route; otherwise() receives the rest.

Effect scope follows its declaration

DeclarationInput
route.effects(...)One queue route
layer.effects(...)Routes combined in that layer
opaque.effects(...)The complete opaque domain at that point
pipeline.effects(...)Everything accumulated so far

Write a general post-process effect

from Infernux.components.serialized_field import serialized_field
from Infernux.renderstack import (
    FullScreenEffect,
    RoutePolicy,
    register_render_effect_feature,
)


class EdgeFadeEffect(FullScreenEffect):
    name = "Edge Fade"
    intensity: float = serialized_field(default=0.35, range=(0.0, 1.0))

    def get_shader_list(self):
        return ["Fullscreen Triangle", "Edge Fade"]

    def setup_passes(self, graph, bus):
        from Infernux.rendergraph.graph import Format
        self.apply_single_source_effect(
            graph, bus,
            output_name="_edge_fade_out",
            pass_name="EdgeFade_Apply",
            shader_name="Edge Fade",
            format=Format.RGBA16_SFLOAT,
            params={"intensity": self.intensity},
        )


register_render_effect_feature(
    "game.post.edge_fade",
    EdgeFadeEffect,
    route_policy=RoutePolicy.MASK_AND_MODIFY,
)

The corresponding asset uses "feature_type": "game.post.edge_fade". Keep this ID stable once assets reference it.

Route policies

  • MASK_AND_MODIFY modifies selected pixels while preserving the surrounding composite.
  • ISOLATE_AND_COMPOSITE renders a route into an isolated image and composites it back.
  • ADDITIVE_EXTRACT contributes an additive signal such as bloom extraction.
  • INLINE requires no isolated route image.
  • CUSTOM_FEATURE owns specialized composition.

Practical rules

  • Put reusable tuning in .effect; put frame structure in RenderPipeline.
  • Use route stages for selected material queues and composite stages for the whole image-so-far.
  • Keep stage IDs stable so serialized slots do not become orphaned.
  • Parameter-only edits should advance an effect revision, not call invalidate_graph() every frame.
  • Place HDR effects such as bloom before tone mapping unless display-space processing is intentional.
  • screen_ui() must be the final pipeline operation.
  • Use low-level define_topology(graph) only when the declarative API cannot express the resource or pass dependency.

RenderStack 与通用后处理

让管线负责一帧的结构，让 Effect 资产负责可复用参数，再由场景通过稳定挂载点把二者组合起来。

本章内容整体关系Effect 资产自定义管线自定义效果实用规则

三类职责

  • RenderPipeline 定义阴影、几何 Route、天空、EffectStage 与屏幕 UI。
  • RenderStack 是场景组件，负责选择管线并挂载有序效果。
  • RenderEffect 是类似材质的可复用资产，保存效果类型与实时参数。

创建一个带 RenderStack 的 GameObject，选择管线，再把 .effect 或 .effectgroup 加入对应阶段。每个阶段都是有序列表：调整 Slot 顺序会改变执行顺序，禁用 Slot 则保留引用但不执行。

EffectStage 是挂载点。

参数修改只推进 Effect Revision；除非注册时明确声明该参数影响拓扑，否则不会重建 Graph。

可复用 Effect 资产

.effect 使用稳定的 Feature ID 与 JSON 参数。

{
  "$schema": "infernux.render_effect",
  "dependencies": [],
  "feature_type": "infernux.post.bloom",
  "parameters": {
    "intensity": 0.8,
    "max_iterations": 5,
    "scatter": 0.7,
    "threshold": 1.0,
    "tint": [1.0, 1.0, 1.0, 1.0]
  }
}

在资产 Inspector 或 RenderStack 的内联 Slot 中修改参数，都会更新同一份共享实例。.effectgroup 保存有序效果链，其中每个条目通过 GUID 和可读、可恢复的 path_hint 引用资产。

{
  "$schema": "infernux.render_effect_group",
  "entries": [
    {
      "entry_id": "bloom",
      "asset": {
        "guid": "",
        "path_hint": "Assets/Rendering/Bloom.effect"
      },
      "enabled": true,
      "overrides": {}
    }
  ]
}

编写自定义管线

Python 是公开入口。新管线覆写 define()；声明式编译器会先验证 Queue 所有权和 Effect Scope，再分配 RenderGraph 资源。

from Infernux.renderstack import Path, Queue, RenderPipeline


class MixedPipeline(RenderPipeline):
    name = "Mixed Pipeline"

    def define(self, pipeline):
        pipeline.frame(hdr=True, msaa=4)
        pipeline.shadows(resolution=4096)
        pipeline.lighting(clustered=True)

        with pipeline.opaque() as opaque:
            with opaque.layer("Stylized Objects") as layer:
                # Queue 1-100 走 Forward。
                layer.forward(Queue(1, 100)).effects("low_queue")

                # Queue 101-200 优先 Deferred，不兼容时回退 Forward+。
                layer.deferred(
                    Queue(101, 200),
                    fallback=Path.FORWARD_PLUS,
                ).effects("middle_queue")

                # 合并处理上面两条 Route 的结果。
                layer.effects("stylized_combined")

            opaque.otherwise().forward_plus()
            opaque.effects("opaque_only")

        pipeline.effects("after_opaque")
        pipeline.sky()
        pipeline.effects("after_sky")

        with pipeline.transparent() as transparent:
            transparent.otherwise().forward_plus()
            transparent.effects("transparent_only")

        pipeline.effects("final")
        pipeline.screen_ui()

Queue 区间包含两端。约定的不透明范围是 0-2500，透明范围是 2501-5000，完整支持范围是 0-9999。同一 Domain 中一段 Queue 只能被一条 Route 领取；otherwise() 消费剩余部分。

声明位置决定 Effect Scope

声明位置接收内容
route.effects(...)单独一条 Queue Route
layer.effects(...)该 Layer 内 Route 的合并结果
opaque.effects(...)此时完整的不透明 Domain
pipeline.effects(...)截至此处累计的全部画面

编写通用后处理

from Infernux.components.serialized_field import serialized_field
from Infernux.renderstack import (
    FullScreenEffect,
    RoutePolicy,
    register_render_effect_feature,
)


class EdgeFadeEffect(FullScreenEffect):
    name = "Edge Fade"
    intensity: float = serialized_field(default=0.35, range=(0.0, 1.0))

    def get_shader_list(self):
        return ["Fullscreen Triangle", "Edge Fade"]

    def setup_passes(self, graph, bus):
        from Infernux.rendergraph.graph import Format
        self.apply_single_source_effect(
            graph, bus,
            output_name="_edge_fade_out",
            pass_name="EdgeFade_Apply",
            shader_name="Edge Fade",
            format=Format.RGBA16_SFLOAT,
            params={"intensity": self.intensity},
        )


register_render_effect_feature(
    "game.post.edge_fade",
    EdgeFadeEffect,
    route_policy=RoutePolicy.MASK_AND_MODIFY,
)

对应资产使用 "feature_type": "game.post.edge_fade"。有资产引用后应保持这个 ID 稳定。

Route Policy

  • MASK_AND_MODIFY 修改选中像素，并保留周围已有 Composite。
  • ISOLATE_AND_COMPOSITE 把 Route 渲染到独立图像，再合成回来。
  • ADDITIVE_EXTRACT 提供 Bloom 提取一类的加法信号。
  • INLINE 不需要独立 Route 图像。
  • CUSTOM_FEATURE 由 Feature 自己管理特殊合成。

实用规则

  • 可复用参数放在 .effect，一帧的结构放在 RenderPipeline。
  • 处理指定材质 Queue 时使用 Route Stage，处理当前整张画面时使用 Composite Stage。
  • 保持 Stage ID 稳定，避免已序列化 Slot 成为孤立项。
  • 只改参数时推进 Effect Revision，不要每帧调用 invalidate_graph()。
  • Bloom 等 HDR 效果通常放在 Tone Mapping 之前，除非明确需要显示空间处理。
  • screen_ui() 必须是管线的最后一个操作。
  • 只有声明式 API 无法表达资源或 Pass 依赖时，才使用底层 define_topology(graph)。
