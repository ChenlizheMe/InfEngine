  • 0.5.2 must demonstrate one documented path joining cross-platform Players, models, schemas, replay, batching, and governed tools.
Delivery tracks

Four tracks, one end-to-end system.

The tracks share infrastructure: platform contracts shape Players, schemas shape control, replay shapes debugging and science, and tool governance shapes both plugins and agents.

Shipping track

  • Android APK/AAB and deployable Web game packages from the same project.
  • Linux Player plus windowless and offscreen execution for CI, servers, and simulation.
  • Explicit platform capabilities instead of silent semantic fallback.

Model data track

  • Standard PyTorch in the Host/Editor for development, training, evaluation, and export.
  • Platform inference runtimes in Players without requiring ordinary users to install a CUDA Toolkit.
  • Measured Torch/DLPack/buffer interchange with documented copy boundaries.

Semantic world track

  • Versioned reflection plus Command/Query schemas shared by UI, Python, and MCP.
  • World snapshot/delta, deterministic replay contracts, and batched create/step/reset.

Trust and research track

  • Engine Tools with schemas, permissions, tests, provenance, resource limits, and lifecycle.
  • Versioned tasks, evaluators, baselines, and replay packages for research use.
  • Research claims only after reproducibility and held-out evaluation gates exist.
Immediate focus

The next three gates.

The immediate work must close real shipping loops. Architecture documents or isolated demos do not pass a release gate by themselves.

Android Player vertical slice

Produce the first installable APK on physical hardware with lifecycle, input, assets, audio, rendering, logs, and a minimal portable scripting contract.

Web portability gate

Validate the Web native-module, Python, rendering, storage, and packaging boundary before promising compatibility or performance.

Torch entry and inference decision

Keep native PyTorch on the Host; compare real Android and Web inference providers using model coverage, latency, memory, package size, fallback behavior, and maintenance cost.
